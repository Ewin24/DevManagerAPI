## Architecture

- **Pattern**: Clean Architecture (strict 4-layer)
- **Layers**:
  - `Domain/` — Entities, Enums, Repository interfaces, Common/AuditableEntity (no dependencies)
  - `Application/` — Services, DTOs, Business logic interfaces + implementations (depends on Domain only)
  - `Infrastructure/` — EF Core DbContext, Repositories, AI/Gemini service, Background services (depends on Domain + Application)
  - `API/` — Controllers, Middleware, Extensions/DI registration, Program.cs (depends on Application + Infrastructure)
- **Key folders**:

## Risks

1. **Zero tests**: No test project means no regression safety. Any change risks breaking existing functionality. No CI gate.
2. **No style enforcement**: Without `.editorconfig`, StyleCop, or analyzers, code consistency depends on individual discipline.
3. **API keys in appsettings**: `appsettings.json` contains the Google AI API key and a remote DB connection string — committed to git (`.gitignore` was only added later for `appsettings.json` but it's still tracked).
4. **No Docker/containerization**: Deployment is manual; no reproducible environments.
5. **Single-developer bus factor**: Git history shows primarily one main contributor (Edwin).
6. **Old school controller pattern**: NOT minimal APIs — `ControllerBase`-based controllers, which means more boilerplate and harder testing compared to .NET 8 minimal APIs.
7. **No CI/CD pipeline**: No `.github/workflows/` — quality checks are entirely manual.
